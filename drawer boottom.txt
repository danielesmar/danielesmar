Sí. En Oracle APEX 24.x puedes conseguir una apariencia prácticamente idéntica a un Bottom Sheet nativo de una PWA, y de hecho APEX ya tiene mecanismos bastante apropiados para hacerlo.
La clave es no intentar convertir el contenido interno del modal en un Bottom Sheet, sino modificar el contenedor externo del diálogo que APEX crea. APEX permite asignar clases CSS directamente al diálogo mediante Dialog → CSS Classes, y los diálogos modales se renderizan como overlays. �
Oracle Docs +1
Además, en las implementaciones modernas de Universal Theme existe incluso el concepto de Drawer con posición Bottom, lo que confirma que el framework ya contempla diálogos que salen desde la parte inferior. �
GitHub

1. Configura la página Modal Dialog
En tu página hija:
Page → Appearance
Configura:
Page Mode:
    Modal Dialog
Después:
Dialog Template:
    Modal Dialog
APEX utiliza automáticamente una plantilla de diálogo para páginas con Page Mode Modal Dialog. �
Oracle Docs
Ahora ve a:
Page
 └── Appearance
      └── Dialog
Y configura:
Width:
    100%

Maximum Width:
    100%

Height:
    Auto

Resizable:
    Off
Y lo más importante:
CSS Classes:
    pwa-bottom-sheet
APEX permite precisamente agregar clases personalizadas mediante Dialog → CSS Classes. �
Oracle Docs
2. Eliminar el padding interno
En el modal agrega:
Template Options
y busca:
Remove Body Padding
Actívalo.
En Theme 42 esto corresponde a:
t-Dialog--noPadding
Oracle documenta esta opción para los diálogos de Universal Theme. �
GitHub
Por lo tanto, si quieres hacerlo directamente mediante CSS Classes también puedes utilizar:
pwa-bottom-sheet t-Dialog--noPadding

4. Pero hay un detalle importante
El CSS anterior hace que el diálogo sea Bottom Sheet, pero necesitamos controlar también la animación.
Un Bottom Sheet nativo normalmente hace:
cerrado

       ↓

┌──────────────┐
│              │
│    página    │
│              │
└──────────────┘


abriendo

       ↑
       │
┌──────────────┐
│              │
│    página    │
├──────────────┤
│    sheet     │
│              │
└──────────────┘
Podemos agregar una animación mucho más natural.
5. Animación de entrada
Agrega:
.pwa-bottom-sheet {

    animation:
        pwaSheetEnter
        .28s
        cubic-bezier(.32, .72, 0, 1)
        both;
}


@keyframes pwaSheetEnter {

    from {

        transform:
            translateY(100%);

        opacity: .8;
    }

    to {

        transform:
            translateY(0);

        opacity: 1;
    }
}
La curva:
cubic-bezier(.32, .72, 0, 1)
produce una sensación bastante más cercana a una animación de componente móvil que un simple:
ease;

7. El backdrop también debe cambiar
APEX genera el overlay detrás del diálogo.
Para una PWA yo utilizaría:
.pwa-bottom-sheet ~ .ui-widget-overlay {

    background: rgba(15, 23, 42, .42) !important;

    backdrop-filter: blur(2px);

    -webkit-backdrop-filter: blur(2px);
}
Pero hay un detalle: dependiendo de cómo APEX genere el DOM, el selector ~ puede no alcanzar el overlay.
Por eso prefiero utilizar:
.ui-widget-overlay {

    background:
        rgba(15, 23, 42, .42) !important;

    backdrop-filter:
        blur(2px);

    -webkit-backdrop-filter:
        blur(2px);
}
Si tu aplicación utiliza otros diálogos que no quieres modificar, entonces podemos limitarlo mediante JavaScript.

10. Botón cerrar
Personalmente, para una PWA bancaria no eliminaría siempre la posibilidad de cerrar.
En lugar de la X de APEX, puedes poner:
             ─────

        Filtrar movimientos

        ...

        Cancelar
o:
╭──────────────────────────╮
│         ─────             │
│                           │
│ Filtrar movimientos   ×   │
│                           │
Pero el × sería tu propio botón, no el botón de APEX.
Por ejemplo:
HTML
<button
    type="button"
    class="pwa-sheet-close"
    onclick="apex.navigation.dialog.cancel(true);">

    <span class="fa fa-times"></span>

</button>
CSS:
.pwa-sheet-close {

    position: absolute;

    top: 42px;
    right: 18px;

    width: 38px;
    height: 38px;

    border: 0;

    border-radius: 50%;

    background: #f1f3f5;

    display: flex;

    align-items: center;
    justify-content: center;

    font-size: 16px;

    cursor: pointer;
}
11. Para que parezca realmente una PWA
Hay otra cosa que te recomiendo mucho.
No uses:
height: 500px;
para el Bottom Sheet.
Utiliza:
height: auto;
max-height: 92dvh;
y:
overflow-y: auto;
Por ejemplo:
.pwa-bottom-sheet .t-Dialog-body {

    max-height: calc(92dvh - 80px);

    overflow-y: auto;

    overscroll-behavior: contain;

    -webkit-overflow-scrolling: touch;
}
dvh es particularmente útil en móviles porque tiene en cuenta mejor las dimensiones dinámicas del viewport.

Y hay una alternativa todavía mejor en APEX 24
Para tu caso, no necesariamente tienes que reinventar todo desde cero.
Oracle APEX/Universal Theme tiene soporte para componentes tipo Drawer, incluyendo una variante Bottom, y existen clases como:
js-dialog-class-t-Drawer--pullOutBottom
además de:
t-Dialog--noPadding
para eliminar el padding. �
GitHub
Por eso, si estás construyendo una PWA bancaria en APEX, mi recomendación sería crear un componente/plantilla reutilizable de Bottom Sheet y no repetir CSS en cada página.
La arquitectura ideal sería:
APEX Application
│
├── Theme Roller
│
├── CSS
│   └── pwa-bottom-sheet.css
│
├── JavaScript
│   └── pwa-bottom-sheet.js
│
├── Modal Page 10
│   └── Bottom Sheet
│
├── Modal Page 20
│   └── Bottom Sheet
│
├── Modal Page 30
│   └── Bottom Sheet
│
└── Modal Page 40
    └── Bottom Sheet
Así puedes tener un estándar visual para toda tu PWA.
Y algo importante: APEX monta los modal dialogs dentro de iframe, así que conviene que el CSS del Bottom Sheet esté pensado específicamente para el DOM del dialog/iframe, no solamente para la página padre. �
Oracle Docs
